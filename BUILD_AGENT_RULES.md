# IFund Builder Rules — verified source, no guessing

**Purpose:** persistent repository-root instructions for human and automated builders. This strategically located historical file is restored and updated rather than deleted as a purported duplicate of AGENTS.md. `AGENTS.md` remains authoritative for detailed current requirements.

1. Identify the real repository, current main commit, protected branch, targeted runtime and affected consumer before work.
2. Read existing implementation, current provider configuration, migration history, release status, prior reviews and all related repositories. Never guess architecture, identity, dependencies, credentials, billing or feature status.
3. Follow current owner decisions and verified source/provider evidence over superseded documentation. Report conflicting/unknown facts explicitly and preserve work until reconciled.
4. Never delete, deduplicate, move or overwrite files, folders, scripts, skills, repositories or policies based on names or apparent redundancy. Confirm every separately located consumer, unique feature and historical data purpose. Preserve uncertain files.
5. Prefer additive, minimal, reversible changes. Keep legacy reference assets readable until safe parity is demonstrated. Never force-push, reset or wholesale-merge divergent work without verified safety.
6. Implement code, tests, backend integration, frontend UI, error paths, mobile behavior, authorization, persistence, documentation and real role-based acceptance. Commits and PRs alone are not completion.
7. Guard owner isolation, Supabase RLS, real payment events, withdrawal rules, financial ledgers, provider permission, consent revocation, token custody, audit and production change controls.
8. Never add mandatory paid tools, provider connections, unverified cloud quotas or GitHub Actions-minute consumption without authorization. Local Playwright is a free developer tool, not an iFund member authorization bypass.
9. Track completed, rejected, deferred, truncated, disabled, simulated and disconnected tasks. Retest affected integration flows and resume unfinished work; never silently discard them.
10. Report what was verified, what was only built, what is blocked by external systems and the exact release commit and target. Preserve rollback and test evidence.
